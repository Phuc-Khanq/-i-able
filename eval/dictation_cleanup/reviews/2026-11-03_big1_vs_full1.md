# big1 against full1

big1 is a LoRA adapter on Qwen3.5-4B trained on the big data set (`engine/voice/cleanup_train/bigset.py`): 7,125
training examples plus 375 held back for the loss, 2 epochs, 1,780 steps, 162.9 min on the 5080 (peak 9.65 GB),
held-back loss 0.0955 before and 0.0094 after. full1 is the earlier adapter (1,088 examples). Both are run the way the
app runs them: llama.cpp b11960, Q8_0, greedy decoding, prompt `cleanup_t1_short`, Khang's PC (RTX 5080).

## Result

| | full1 | big1 |
| --- | --- | --- |
| big1 test, 2,500 cases, automatic | 2,389 (95.6%) | **2,441 (97.6%)** |
| Same 150 random cases, full pass by Khang's rule | 132 (88%) | **141 (94%)** |
| Silent guesses (two meanings, one picked without showing both) | 14 / 380 | **0 / 380** |
| Clean sentences changed | 6 / 378 | 4 / 378 |
| Possible invented facts flagged | 7 | 8 (see below) |
| Broken JSON answers | 1 | 0 |
| Dev, 67 hand-written cases, automatic | 64 | 65 |
| Dev, full pass by Khang's rule | 61 (91%) | **63 (94%)** |
| Latency on the 2,500, p50 / p90 / p99 | 294 / 345 / 463 ms | 289 / 338 / 444 ms |

After one epoch big1 was already better than full1 (2,430 automatic, 2 silent guesses); the second epoch added a
little more (2,441, 0), so the final adapter is the one to use.

**How far to trust it.** The 2,500 test cases come from the same generator as big1's training data (different
sentences and misheard terms, same templates and style), so part of big1's gain there is learning that style. Dev
was written separately and isn't from the generator, but it was used to tune the prompts. On dev the gain is 2 cases
(S11, X08), within noise. The human-written hidden set is still the number to trust.

Method for the 150: the same cases as the full1 hand check (`2026-11-03_big1_test_sample_full1.md`, seed 150). 128
of big1's answers are word for word the same as full1's and keep their verdicts; the 22 that differ were judged by
Claude with Khang's rule. Dev: blind sheet `2026-11-03_dev_big1.csv`, scored in `2026-11-03_dev_big1_score.md`.

## What big1 fixed (in the 150)

- Word-list words no longer offered as alternatives (all 5: quinoa, takeout, quarterback, graduation, reservation).
- Misheard terms: syllabus (was "bus"), guest list (was kept as "guest lift").
- Small words: "for Noah", "Can I switch my sertraline to the evening?".

## What is still wrong, or new

- **Still wrong (8 in the 150):** hand controls -> "brake controls", AFO -> "axe", receipt kept as "recipe", Discord
  -> "scoreboard" (with Discord on the word list), and the four small-word cases (a question became a statement, or
  "is" dropped). Two of these are the unfair cases where the noise dropped "can" or "will".
- **New (1 in the 150):** B1232 "the fifteend of March" -> "the end of March". A date changed, and the app's guard
  lets it through: it doesn't read a misspelled number word as a number.
- **New pattern, outside the sample:** "medic care" -> **Medicaid** (meant Medicare) in all 3 cases that have it
  (B0063, B1311, B1523). Medicaid is a training term and Medicare a test term, so big1 learned one and maps the other
  to it. The guard blocks all 3 (name added), and the user gets their words back without fillers.
- The other flagged inventions are right answers the flag can't see (Thanksgiving, Discord, W-2, Minecraft, "five
  thousand" from "thowsand").

## The app's guard (check_cleanup) on big1's 2,500 answers

12 blocked (full1: 13): 7 of them answers that failed the automatic checks (the Medicaid ones among them) and 5
good answers (0.2%: EpiPen, nonprofit, AFO, "five thousand", "medication"). It catches none of the 9 failures in
the 150: they are wrong meanings, not wrong words.
