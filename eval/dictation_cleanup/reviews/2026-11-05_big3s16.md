# big3s16: rank 16 beats rank 32 on the same data

big3s16 is the run of 2026-11-05 (08:42 to 11:46): big3s with **one change, LoRA rank 16 / alpha 32 instead of 32 / 64**.
Everything else is the same: the data (`data/cleanup_train/big3s_train.jsonl`, 8,000 examples, 3,153 different answers),
the seed, the split (7,598 trained, the same 402 held back as whole sentences), the order, 2 epochs, 1,898 steps, the
learning rate and its schedule. Its first loss check matches big3s's to four decimals. 30.5 million trainable numbers
(big3s 61 million). 182.1 min on the 5080, peak 9.66 GB (big3s 175.4 min, 10.21 GB). The later steps ran at about
6.5 s instead of 4.4 s while other programs were open on the PC, so the time says nothing about the rank. Scoring as the
app runs it: llama.cpp b11960, Q8_0, greedy, prompt `cleanup_t1_short`, Khang's PC (RTX 5080). The test file is the
unchanged big1_test.csv (sha256 ec2b1b0aa648c0e3).

Head to head on the fair 2,301 (automatic, not hand-checked with Khang's rule):

- **big3s16 against big3s: wins 17, loses 2.** Same data, so this is the rank alone.

Dev: big1, big3s16 and big3s16's epoch 1 all fail the same two cases (M16, M25).

- From the end of epoch 1 on, rank 16 is lower on **both** kinds of new data. It also ends lower on its own training
  data (0.0006 vs 0.0009). So rank 32 isn't simply "more room to memorize": it does worse everywhere.
- One guess, not tested: with alpha set to twice the rank, rank 32 has the same scale but twice as many directions to
  change, so each step moves the model further. That acts like a higher learning rate. If that's right, a lower
  learning rate at rank 16 could also help. That's the cheapest next test.
- The gap is still there: at the end, held-back sentences 0.0133 against training 0.0006 (22 times). Both new-data losses
  stop improving after step 1,500 (0.0133 to 0.0133, test cases 0.0195 to 0.0200). Epoch 2 adds little: the fair 2,301
  go from 2,274 to 2,277, and the whole test stays at 2,432.
- The test-case loss, 0.0200, is close to big1's 0.0190. Part of big1's edge there is the terms it trained on.

## What changed in the answers

**Gone with rank 16 (big3s's habits):**

- Spoken numbers as digits: "two point one" stays words (big3s: "2.1", "2.0.1"), "three fifty" stays (big3s: "350
  degrees"). 0 cases, like big1.
- Clean sentences: "thirtieth" stays (big3s: "thirtyeth"), "add thickener" stays (big3s: "add a thickener"), "eating
  takes me" stays (big3s: "My eating takes"), "kibble, please" keeps "please" at the end.
- Misheard words fixed that big3s left or got wrong: autopay (big3s: "my light"), receipt (twice; big3s: "recipe"),
  suction machine, carry-on, curb cut, W-2 (twice), Discord server.

**big3s16's 4 changed clean sentences:** three put a "please" in or move it ("Please remind the evening aide...",
"Please send me the menu...", "Please play something relaxing."), and "love you talk soon" -> "I love you, talk soon."
big1 changes three of the same four. None of big3s16's add "the" or "a" (big1 adds "the" once: "pay the estimated taxes").
So at this size and rank the "add the" habit doesn't show on clean sentences. It showed in big3 (rank 32, 24,000
examples).

**Where big3s16 is worse than big1: a few confident wrong guesses.** These are the main risk:

- "hard worm test came back negative" -> "The **HIV** test came back negative." (big1 left it as heard)
- "accessible you uh knit" -> "accessible **yoga class**" (big1: "unit"; the scorer doesn't flag this one)
- "the afo on my rite I mean foot" -> "The **ankle** on my right foot..." and "The half oh" -> "The **HFO**" (big1: AFO
  both times)
- "pred knee zone" -> "**PRP** knee zone" (big1: prednisone)
- "my cardio just uhh changed..." -> "My cardio changed..." (big1: cardiologist)

None of these were marked "uncertain". Whether the app's guard (`check_cleanup`) would block them is unmeasured.

## What it means

1. **Rank 16 is the right setting.** Same data, only the rank changed: rank 16 wins on the test (+14), the fair split
   (+15), clean sentences (4 vs 7), dev (65 vs 64), spoken numbers and both loss checks. The trainer's default is already
   16; big2, big3s and big3 passed `--rank 32`. Use 16 from now on.
2. **Earlier conclusions that need a second look.** big2, big3s and big3 were all rank 32. "big3s doesn't beat big1"
   was partly the rank. "Three times the data made it worse" (big3 vs big3s) is still true at rank 32, but untested
   at rank 16.
3. **big1 stays the app's model for now.** big3s16 ties it on the fair cases and on dev, and does better on terms no run
   trained on (86 vs 84). But it makes more confident wrong guesses on medical words (HIV, AFO, PRP). Choose one of the two
   before the hidden test, so the hidden test is run once, on one model.
4. **Still overfitting to the generator.** Rank doesn't change that: the new-data losses flatten after step 1,500 while
   the training loss keeps falling. New sentences from new sources stay the way to more data.

## Next tests (each at rank 16)

- **Lower learning rate (1e-4) on big3s's data, about 3 h.** Tests the "steps too big" guess above.
- **big3's 24,000 at rank 16, about 7 h, overnight.** Does more data help once the rank is right? This bears directly on
  the 100,000 goal.
- **The "add the" fix in the data.** Less urgent: it doesn't show at this rank and size.
